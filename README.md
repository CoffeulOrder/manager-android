# ORMO 관리자앱

대학교 안 카페 주문 앱 "ORMO"의 **점주용 태블릿 앱**입니다.
주문 접수·거절·환불, 영업 상태, 메뉴 관리, 매출, 설정을 다룹니다.

> **⚠️ 아직 서버에 연결되어 있지 않습니다. 이 상태로는 매장에서 사용할 수 없습니다.**
> - 고객의 주문이 들어오지 않습니다. 화면의 주문·메뉴·지난 매출은 앱에 넣어 둔 예시 값입니다.
> - **환불·거절·자동 취소를 해도 돈이 돌아가지 않습니다.** 결제 취소를 아무 데도 요청하지 않고 성공으로 처리합니다.
> - 로그인은 아무 아이디·비밀번호나 통과합니다.
> - 모든 데이터는 앱 메모리에만 있어 앱을 다시 켜면 처음 값으로 돌아갑니다.
>
> 붙여야 할 곳은 [서버 연동](#서버-연동), 배포 전에 정리할 것은 [출시 전 확인할 것](#출시-전-확인할-것)을 보세요.

## 기술 구성
- Kotlin · Jetpack Compose · Material 3 · 단일 Activity · ViewModel + StateFlow
- 태블릿 가로 고정, 라이트 테마. 디자인은 Figma `UIUX-Design` > `Design [사장님 웹]`(기준 1280x800)을 따르고,
  화면 크기가 다르면 같은 비율로 확대·축소합니다. 브랜드 색 `#298DFF`, 글꼴 Pretendard(`licenses/Pretendard-OFL.txt`)
- 시스템 상태바·내비게이션 바를 숨기고, 화면이 자동으로 꺼지지 않게 합니다.
- `minSdk 26` / `compileSdk 37` / `targetSdk 35` / JDK 17 (AGP 9.5.1, Kotlin 2.4.21, Gradle 9.9.1, Compose BOM 2026.09.00)

## 실행 방법

### Android Studio (권장)
1. 최신 안정 버전 Android Studio로 이 폴더를 엽니다. (AGP 9.5를 지원하는 버전이어야 합니다.)
2. Gradle Sync 후, 태블릿 가로 에뮬레이터(예: *Pixel Tablet*, 또는 1194x834dp 근처 프로파일)를 만들어 `app`을 실행합니다.
3. SDK Platform **37**과 Build-Tools **36.0.0**이 필요합니다.

### 명령줄
```bash
./gradlew :app:assembleDebug     # APK 빌드
./gradlew :app:installDebug      # 연결된 에뮬레이터/기기에 설치
./gradlew :app:testDebugUnitTest # 단위 테스트
```
> `gradle/wrapper/gradle-wrapper.jar`와 `gradlew` 스크립트는 포함되어 있지 않을 수 있습니다.
> 그 경우 Android Studio로 열면 `gradle-wrapper.properties`(Gradle 9.9.1)를 보고 알아서 받아 쓰고,
> 명령줄을 쓰려면 Gradle이 설치된 곳에서 한 번 `gradle wrapper`를 실행하세요.

> `gradle.properties`에 `-Dfile.encoding=UTF-8`을 넣지 마세요. Windows 사용자 폴더 이름이 한글이면
> 단위 테스트가 `ClassNotFoundException: GradleWorkerMain`으로 실패합니다.

## 화면과 기능

### 로그인
- 아이디·비밀번호로 로그인합니다. 첫 로그인이면 비밀번호(8자 이상, 영문+숫자)를 바꾼 뒤 들어갑니다.
- 틀리면 안내하고, 여러 번 틀리면 남은 시간 동안 버튼이 꺼집니다.

### 주문
- **주문 보드**: 접수 대기 | 제조중 | 픽업 대기. `수락 → 조리 완료 → 픽업 완료`. `조리 완료`는 10초 안에 되돌릴 수 있습니다.
- **거절**: 사유 4개 중 선택(품절이면 "오늘만 품절로 바꾸기").
- **미수령**: 픽업 대기 20분이 지난 카드의 `정리하기`(환불 없음).
- **자동 취소**: 접수 대기로 10분이 지나면 전액 환불로 취소합니다.
- **환불**: `오늘 내역`에서 픽업 완료·미수령 주문을 골라 사유를 정합니다(전액, 비밀번호 없음).
- 결제 취소가 실패하면 주문 상태를 그대로 두고 `다시 시도`를 보여줍니다.
- **고객 취소**: 접수 대기 주문을 고객이 취소하면 카드를 취소 모습으로 5초 보여준 뒤 뺍니다. 거절 사유를 고르는 중이었거나
  이미 취소된 주문을 처리하려 하면 안내 창을 띄웁니다. 환불은 서버가 하므로 앱은 결제 취소를 부르지 않습니다.
  앱은 `OrderRepository`의 상태가 `CUSTOMER_CANCELED`로 바뀌는 것을 보고 처리합니다.

### 알림
- **새 주문**: 스낵바와 알림음(3초마다). 수락·거절하거나 닫으면 멈춥니다.
- **자동 취소 2분 전**: 남은 시간이 빨간색이 되고 알림음이 한 번 울립니다.
- **소리 꺼짐**: 미디어 음량이 0이거나 블루투스(A2DP)가 연결되면 안내합니다.
- 스낵바는 왼쪽 아래에 최대 3개까지 쌓입니다. 알림음은 기기 기본 알림음입니다.
- **알림과 자동 취소 확인은 앱 화면이 보일 때만 동작합니다.** 백그라운드 알림(푸시)은 없습니다.

### 인터넷 끊김
- 끊기면 `인터넷 연결이 끊겼어요` 안내가 다시 연결될 때까지 떠 있고, 카드·환불 버튼이 흐려집니다.
- 끊긴 동안에는 주문 처리·환불·영업 상태·품절·메뉴·영업시간 변경을 **막고**, 모아 두었다가 보내지 않습니다.
  자동 취소(환불)와 잠시 중지 자동 해제도 연결된 뒤에 처리합니다.
- 기기의 실제 인터넷 상태를 봅니다(`network/Connectivity.kt`). 서버만 응답하지 않는 경우는 알 수 없습니다.

### 영업 상태
상단 버튼에서 바꿉니다.
- **잠시 중지**: 시간(10·20·30·60분·직접 다시 열기)과 사유를 고릅니다. 시간이 끝나면 다시 열립니다.
- **마감**: 접수 대기가 있으면 한 번 더 묻고, 모두 취소(전액 환불)한 뒤 마감합니다. 이미 받은 주문은 계속 처리합니다.

### 메뉴 관리
- **품절**은 영업 중에도 스위치로 바로 바꿉니다(비밀번호 없음). 접수 대기 주문에 있는 메뉴면 알려줍니다.
- **옵션 상세**: 모든 메뉴 또는 메뉴별로 품절을 바꿉니다. 일부 메뉴만 품절이면 `일부 품절`로 표시합니다.
  필수 옵션 때문에 메뉴를 팔 수 없게 되면 경고합니다.
- **추가·수정·삭제·숨김**은 **마감**일 때만 열리고 2차 비밀번호를 묻습니다.
  - 메뉴: 이름·가격·설명·카테고리·옵션 연결·`고객에게 보이기`. 이름은 겹칠 수 없습니다.
  - 삭제는 10초 동안 되돌릴 수 있습니다. 숨긴 메뉴는 카테고리 맨 아래에 모입니다.
  - 옵션 그룹은 새로 만들어 메뉴에 연결합니다.

### 매출과 2차 비밀번호
- `매출` 탭에 들어갈 때와 메뉴를 추가·수정할 때 4자리 2차 비밀번호를 묻습니다. 처음 필요할 때 직접 정합니다.
- 5번째 틀릴 때부터 30초씩 기다립니다. 화면을 나갔다 들어오면 다시 묻습니다.
- 일간·주간·월간(그래프/달력)을 봅니다. 오늘 매출은 앱 안의 주문으로 계산합니다.

### 설정
- **영업시간**: 월~일·공휴일을 따로 정합니다(24시간, 자정을 넘기는 영업은 지원하지 않음). 고객 앱 안내용이라 자동으로 열거나 닫지 않습니다.
- **2차 비밀번호 바꾸기**: 지금 → 새 → 한 번 더.
- **로그아웃**: 영업 중·잠시 중지에는 막고 마감을 안내합니다.

부분 환불, 환불 메모 전송, 백그라운드 알림, 불러오는 중·불러오기 실패 화면,
서비스 점검·로그인 만료·업데이트 필요 화면.

## 서버 연동
네트워크를 붙일 때 `AndroidManifest.xml`에 `INTERNET` 권한을 추가하세요.

### 결제 취소
- 인터페이스: `payment/PaymentGateway.kt` — `suspend fun cancel(orderId, reason, amount): Result<Unit>`
- 지금 구현: `payment/FakePaymentGateway.kt` — **아무것도 요청하지 않고 성공**합니다.
- 교체 지점: `ui/OrderViewModel.kt`의 `Factory` 안 `paymentGateway = FakePaymentGateway()` 한 줄을,
  **자사 서버의 결제 취소 엔드포인트를 호출하는 구현**으로 바꿉니다. 포트원 결제 취소 API는 서버가 호출합니다.
- **포트원 API 시크릿·키는 앱에 넣지 않습니다.**
- 거절·환불은 "결제 취소 성공 → 상태 변경" 순서입니다.

### 로그인
- 인터페이스: `auth/AuthGateway.kt` — `login`, `changePassword`, `logout`.
  `login`은 `Success(firstLogin)` / `Rejected` / `Locked(retryAfterSeconds)`를 돌려주고, 통신 오류는 `Result.failure`입니다.
- 교체 지점: `MainActivity.kt`의 `FakeAuthGateway()` 한 줄.
- 토큰 저장, 30일 로그인 유지, 저장된 토큰으로 바로 들어가기는 아직 없습니다.
- 틀린 횟수와 잠금 시간은 서버가 셉니다. 비밀번호는 앱에 저장하지 않습니다.

### 그 밖에 서버로 옮겨야 하는 것
| 대상 | 지금 위치 |
|---|---|
| 주문(실시간 수신 포함), 자동 취소 시간 | `data/OrderRepository.kt`, `data/MockOrders.kt` |
| 메뉴·옵션·품절 | `data/MenuRepository.kt` |
| 영업 상태 | `ui/OrderViewModel.kt` |
| 영업시간 | `ui/SettingsViewModel.kt` |
| 지난 매출 | `data/MockSales.kt` |
| 2차 비밀번호와 틀린 횟수 | `ui/PinViewModel.kt` |

메뉴별 옵션 품절을 서버가 지원하지 않으면 옵션 상세의 메뉴별 스위치를 빼야 합니다.

### 서버 연동 전에 화면 확인하기
| 화면 | 방법 |
|---|---|
| 로그인 실패 | 아이디에 `fail` |
| 5번 실패(30초 잠금) | 아이디 `fail`로 5번 |
| 첫 로그인 · 비밀번호 바꾸기 | 앱을 켠 뒤 첫 로그인 |
| 고객 취소 | 하단의 `테스트 고객 취소` (개발 빌드에만 보임, 가장 오래된 접수 대기를 취소) |
| 이미 취소된 주문 안내 | `테스트 고객 취소`를 **길게 누르고** 5초 안에 그 주문의 `거절` 누르기 |
| 인터넷 끊김 | 태블릿의 와이파이·데이터 끄기 |
| 새 주문 | 하단의 `테스트 주문 추가` (개발 빌드에만 보임, 영업 중일 때) |
